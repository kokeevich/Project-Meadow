# Plans.md — Project Meadow

> Рабочее название проекта: **Project Meadow**  
> Жанр: Cozy Farm Management / Time Management  
> Визуальный стиль: Stylized Low-Poly 3D / игрушечная диорама  
> Основной движок: Unity  
> Язык: C#  
> Основные платформы на этапе разработки: PC + Android  
> Режим: Single-player  
> Статус: Pre-production / начало реализации

---

# 1. Концепция

Project Meadow — уютная low-poly 3D игра, вдохновлённая классическими играми в духе «Весёлой фермы», но с современным визуальным стилем, постоянной домашней фермой и постепенной автоматизацией.

Основная цель игры — дать игроку короткие, насыщенные игровые сессии, в которых постоянно происходит что-то приятное: животные едят, производят ресурсы, игрок собирает продукты, перерабатывает их, выполняет заказы и открывает новые возможности.

Игра не должна вызывать сильный стресс. Игрок может оптимизировать прохождение и получать дополнительные награды за скорость, но отсутствие идеального результата не считается проигрышем.

Главная эмоция:

> «Я занят чем-то приятным, постоянно что-то улучшаю и на некоторое время забываю о внешних проблемах».

---

# 2. Основные принципы дизайна

1. Простое управление — всё основное управление выполняется кликом или нажатием.
2. Игрок почти всегда видит результат своего действия.
3. Каждые несколько уровней открывается что-то новое.
4. Уровни короткие и подходят для прохождения за одну игровую сессию.
5. Таймер не должен быть обязательным условием победы.
6. Животные должны ощущаться живыми, а не просто производственными станками.
7. Производственные цепочки постепенно усложняются.
8. Ранние ручные действия постепенно можно автоматизировать.
9. Домашняя ферма визуально развивается вместе с прогрессом игрока.
10. Игра должна оставаться понятной без длинных обучающих текстов.
11. Важные действия сопровождаются приятными анимациями и звуками.
12. Никаких механик, существующих только ради искусственного удержания игрока.

# 5. Core Loop

Основной цикл уровня:

```text
Посадить / вырастить корм
          ↓
Животное находит корм
          ↓
Животное производит ресурс
          ↓
Игрок собирает ресурс
          ↓
Ресурс поступает на склад
          ↓
Игрок продаёт ресурс
или отправляет его в переработку
          ↓
Получает деньги / новый продукт
          ↓
Покупает животных и улучшения
          ↓
Производство ускоряется
          ↓
Выполняется цель уровня
```

Долгосрочный цикл:

```text
Пройти уровень
     ↓
Получить 1–3 звезды
     ↓
Открыть новый контент
     ↓
Улучшить домашнюю ферму
     ↓
Открыть следующую группу уровней
     ↓
Освоить новую производственную цепочку
```

# 6. Управление

Выбран вариант C:

- корм выращивается на специальных небольших участках;
- животные самостоятельно находят доступный корм;
- продукты появляются физически на земле;
- игрок нажимает на продукт, чтобы собрать его;
- позднее появляется автоматический сборщик.

## PC

- ЛКМ — взаимодействие;
- колесо мыши — приближение/отдаление;
- удержание средней кнопки или ПКМ — вращение камеры;
- Esc — пауза.

## Mobile

- Tap — взаимодействие;
- Pinch — масштабирование;
- Drag двумя пальцами или отдельная зона — вращение камеры;
- кнопка паузы — интерфейс.

Главные действия должны одинаково хорошо работать мышью и touch.

# 7. Камера

Тип:

- perspective camera;
- вид сверху под углом;
- стиль миниатюрной диорамы;
- ограниченное вращение;
- ограниченный zoom.

Не требуется:

- свободная камера от первого лица;
- камера от третьего лица;
- сложные cinematic-системы.

На MVP можно начать с фиксированной камеры и добавить вращение после того, как основной цикл заработает.

# 8. Первый MVP

Цель MVP:

Проверить, приятно ли играть в базовый цикл.

## MVP должен содержать

- [ ] одна игровая сцена;
- [ ] камера;
- [ ] участок с кормом;
- [ ] возможность выращивать корм;
- [ ] две курицы;
- [ ] движение куриц;
- [ ] поиск корма;
- [ ] поедание корма;
- [ ] появление яйца;
- [ ] яйцо физически лежит на земле;
- [ ] сбор яйца кликом;
- [ ] склад;
- [ ] ограничение вместимости склада;
- [ ] грузовик;
- [ ] отправка яиц на продажу;
- [ ] получение монет;
- [ ] цель «Продать 10 яиц»;
- [ ] экран завершения уровня;
- [ ] возможность перезапустить уровень;
- [ ] базовые звуки;
- [ ] простая анимация курицы;
- [ ] простая UI-панель ресурсов.

## MVP НЕ должен содержать

- главное меню;
- сюжет;
- домашнюю ферму;
- несколько животных;
- много зданий;
- магазин косметики;
- систему достижений;
- полноценное сохранение;
- кооператив;
- большое количество графики.

## Definition of Done

MVP считается успешным, если:

1. Игровой цикл полностью работает без ручных действий разработчика.
2. Уровень можно пройти от начала до конца.
3. Игрок понимает основные действия без объяснения разработчика.
4. Сбор продуктов ощущается приятно.
5. В игре нет критических ошибок в течение нескольких последовательных прохождений.
6. Прототип хочется запустить повторно хотя бы ещё один раз.

# 12. Система звёзд

Каждый уровень имеет:

## Обязательная цель

Требуется для прохождения.

Например:

- произвести 10 сыров.

## Звезда 2

Дополнительная экономическая цель.

Например:

- заработать 1200 монет.

## Звезда 3

Оптимизационная цель.

Например:

- закончить уровень быстрее 5 минут.

Игрок может продолжить прохождение при одной звезде.

Звёзды используются для:

- открытия дополнительных декораций;
- отдельных косметических наград;
- дополнительных участков домашней фермы;
- необязательного контента.

Не блокировать основное прохождение чрезмерными требованиями по звёздам.

# 14. «Живые» животные

Для создания эмоциональной связи добавить небольшие необязательные действия.

Примеры:

Курица:

- бегает за другой курицей;
- пытается подпрыгнуть;
- смотрит в камеру;
- встряхивает крылья.

Корова:

- ложится;
- мычит;
- смотрит на игрока;
- виляет хвостом.

Овца:

- прыгает;
- иногда падает;
- трётся о забор.

Эти действия почти не влияют на экономику.

Главная задача — сделать ферму живой.

# 15. Система взаимодействия

Создать единый интерфейс:

```csharp
public interface IInteractable
{
    void Interact();
}
```

Игрок нажимает на объект.

InteractionSystem:

1. получает позицию мыши/touch;
2. выполняет Raycast;
3. ищет IInteractable;
4. вызывает Interact().

Через систему взаимодействуют:

- продукты;
- здания;
- поля;
- животные;
- грузовик;
- UI-представления мира.

# 19. Склад

Создать InventoryService.

Ответственность:

- хранение ресурсов;
- добавление предметов;
- удаление;
- проверка количества;

# 20. Продажа

Игрок выбирает товары для грузовика.

Система продажи:

1. Проверить наличие товара.
2. Удалить товар со склада.
3. Запустить поездку грузовика.
4. По завершении добавить деньги.
5. Грузовик возвращается.

На MVP можно сделать мгновенную продажу.

Анимацию поездки добавить позже.

# 54. Приоритеты

При любом сомнении использовать порядок:

```text
1. Работает ли core gameplay?
2. Приятно ли играть?
3. Понятно ли игроку?
4. Есть ли хороший feedback?
5. Хорошо ли выглядит?
6. Есть ли дополнительный контент?
```

Не делать красивую второстепенную систему, если core gameplay ещё не завершён.

---

# 55. Основной принцип разработки

Каждая новая система должна отвечать хотя бы на один вопрос:

- делает ли она игру приятнее;
- создаёт ли новое решение;
- усиливает ли чувство прогрессии;
- усиливает ли атмосферу;
- помогает ли игроку понимать происходящее.

Если нет — система пока не нужна.

# 57. Критерий продолжения проекта

После первого MVP ответить на пять вопросов:

1. Приятно ли нажимать на продукты?
2. Приятно ли наблюдать за животными?
3. Есть ли ощущение постоянной занятости?
4. Хочется ли оптимизировать прохождение?
5. Хочется ли сыграть следующий уровень?

Если минимум 4 ответа из 5 — «да», продолжать развитие текущего ядра.

Если нет — сначала менять core gameplay, а не добавлять новый контент.

---

# 58. Финальная цель

Project Meadow должен ощущаться не как сложный симулятор фермы, а как маленькое комфортное место, куда приятно вернуться на несколько вечеров.

Главное:

> Короткие понятные задачи + приятные взаимодействия + живые животные + визуальный рост фермы + постоянное открытие нового контента.
